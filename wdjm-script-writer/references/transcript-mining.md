# Transcript Mining

Load this file only when the user has provided a transcript, call notes, or source material and wants beliefs / language / proof extracted from it.

## What transcript mode is good for

Use transcript mining when the user wants to:

- Discover new beliefs that aren't in the bank yet
- Uncover contrarian angles Joseph teaches in conversation but hasn't packaged
- Pull exact language patterns Joseph naturally uses
- Identify recurring pain points from a mentorship-call audience
- Find mentor-like reframes worth amplifying
- Extract proof points or stories worth turning into content

## What transcript mode should NOT do by default

**Do not try to extract every possible belief from a large transcript** unless the user explicitly asks for exhaustive extraction.

**Default goal:** Extract the most persuasive **5 to 15** belief candidates related to the offer. Identify the strongest contrarian versions. Identify matching proof and angle options. That's it.

Exhaustive extraction is expensive and produces a flat list with no priority signal. Curated extraction produces a usable shortlist.

## The three modes — ask which one if unclear

When a transcript is provided, the user wants one of three things. If they didn't say which, **ask** before doing the work:

### A. Extract-only

*Extract candidate beliefs, angles, proof lines, and contrarian reframes. Do not write scripts.*

Useful when the user is building a belief bank, planning a campaign, or wants to see the raw material before deciding what to do with it.

### B. Extract + recommend

*Extract beliefs, organize them, and recommend which are strongest for persuasion.*

Useful when the user wants curatorial judgment — "tell me which of these would make the best videos."

### C. Extract + write

*Extract beliefs and then generate scripts from the strongest ones.*

Useful when the user wants the full pipeline: transcript in, scripts out.

## Workflow

### Step 1 — Read for patterns, not exhaustiveness

Scan the transcript and identify recurring instances of:

- **Pain points** — what the audience keeps complaining about
- **Bottlenecks** — what's actually keeping them stuck (often different from the pain points they name)
- **Old beliefs** — what they say they think
- **New beliefs** — what Joseph offers in response
- **Emotional language** — words and phrases that carry weight
- **Proof moments** — stories, numbers, or examples Joseph uses to ground a point
- **Repeated reframes** — corrections he makes more than once
- **Specific phrases worth preserving** — Joseph's natural wording on a topic

### Step 2 — Convert findings into belief candidates

For each candidate, capture this shape:

```
- Old belief: [what they currently think]
- New belief: [what should replace it]
- Category: [from belief-bank.md categories]
- Contrarian: [yes / no]
- Proof support: [the moment or quote in the transcript that proves it]
- Best script mode: [from story-modes.md]
```

The proof-support field is the most important one — without a real quote or moment from the transcript, the belief isn't *derived from the source*, it's just paraphrased from the bank.

### Step 3 — Present a shortlist

If the user hasn't yet chosen which beliefs to use:

1. Surface the **5–15 strongest** belief candidates in the shape above
2. **Recommend** which 3–5 are best for persuasion right now (sharpest reframe, strongest proof, clearest audience match)
3. Ask whether to proceed to scripts, and if so, which beliefs to write from

### Step 4 — Write from the chosen beliefs

If the user already said *"extract and write,"* skip the shortlist step and:

1. Internally pick the top 3–5 candidates using the same criteria
2. Surface a one-line summary of which beliefs you chose ("Writing from these three: …")
3. Write the scripts using the main SKILL.md workflow

## Recommendation rules

- **For quick scripting:** user-supplied beliefs are faster — don't push transcript mining if the user already knows what they want to say.
- **For strategic campaign building:** transcript extraction is more powerful — it surfaces language the bank doesn't have yet.
- **For very large transcripts:** if the user has hours of material, recommend dedicated belief-extraction passes (one transcript at a time, or sectioned) rather than trying to do everything in one shot.

## Honesty rules for transcript-derived beliefs

- **Don't paraphrase the bank and call it transcript-derived.** If a belief is really just the bank's version, say so.
- **Quote the source moment** when surfacing a transcript-derived belief, so the user can verify it.
- **Flag uncertainty.** If a belief is only weakly supported in the transcript, mark it weak — don't promote it to confident.
